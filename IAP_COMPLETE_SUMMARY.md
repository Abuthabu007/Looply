## 🔐 Security Implementation

### 1. OAuth 2.0 Setup
- **Client ID**: Generated by Google Cloud
- **Client Secret**: Encrypted with Cloud KMS
- **Scopes**: openid, email, profile
- **Grant Type**: authorization_code

### 2. Access Control
```hcl
# Three levels of authorization:

# Level 1: User-Based
iap_admin_authorized_users = [
  "user:john@looply.io"
]

# Level 2: Group-Based
iap_admin_authorized_users = [
  "group:admins@looply.io"
]

# Level 3: Role-Based (IAM)
roles/iap.httpsResourceAccessor
```

### 3. Encryption & Secrets
- OAuth client secrets in Cloud KMS
- Service account keys managed
- No secrets in code/state file

### 4. Audit Trail
- All access attempts logged
- Failed authentications tracked
- Cloud Logging → Cloud Storage

## 🛠️ Troubleshooting

### Issue: OAuth Consent Screen Error
**Solution**:
```bash
gcloud iap oauth-brands create \
  --application_title="Looply" \
  --support_email=security@looply.io
```

### Issue: Access Denied (403)
**Solution**:
1. Verify user in `iap_admin_authorized_users`
2. Check IAM roles assigned
3. Wait 5-10 minutes for propagation
4. Clear browser cookies and retry

### Issue: Client ID Not Found
**Solution**:
1. Ensure OAuth brand created
2. Re-run `terraform apply`
3. Check outputs: `terraform output iap`
